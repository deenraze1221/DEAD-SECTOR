# Кооператив Godot: до четырёх игроков

Скачайте одну и ту же версию проекта. Каждый открывает `godot/project.godot` в Godot 4.6 Standard и запускает F5. Браузер и ChatGPT для матча не нужны.

## По локальной сети

1. Хост: PLAY → LAN → HOST LAN LOBBY.
2. Его локальный IP показан в лобби. Друг: PLAY → LAN → вводит этот IP → JOIN LAN.
3. Когда игроки заняли слоты, хост нажимает START MATCH. Через пять секунд начинается игра.

Отдельный Node.js-сервер не нужен. Godot слушает UDP-порт 3001. Разрешите Godot доступ к частной сети в брандмауэре Windows. Можно использовать виртуальную LAN/VPN: тогда вводится адрес хоста в этой сети. IP вида 127.0.0.1 подходит только для двух запусков на одном компьютере.

## Через интернет / Render

Используется тот же сервер из `server/index.js`, что и для HTML, но комнаты Godot отделены маршрутом `/godot`.

На Render обновите репозиторий/сервис до этой версии:

- Runtime: Node, версия 22 или новее.
- Build command: `npm ci && npm run build`
- Start command: `npm run server`
- Порт берётся из переменной `PORT` Render. Файл `render.yaml` уже содержит конфигурацию.

Хост открывает PLAY → SERVER, вводит `wss://имя-сервиса.onrender.com` и нажимает OPEN SERVER LOBBY. Появится восьмизначный код; COPY копирует его. Друг выбирает JOIN BY CODE в главном меню, вводит **тот же адрес сервера** и код. После входа всех игроков хост запускает матч.

Адрес сохраняется. `/godot` добавляется автоматически. Если бесплатный сервис спит, подключение повторяется: пробуждение Render занимает время. Режим локального тестирования сервера: `npm ci`, `npm run build`, `npm run server`; в Godot укажите `ws://локальный-IP:3000`.

## Что синхронизируется

- Четыре слота, код, общий seed города, запуск матча.
- Солдаты с шеей, оружием в точках хвата, поворотом головы/рук, ходьбой и фонариком; союзники на компасе.
- Хост рассчитывает зомби, попадания, урон, снаряды, волны и ловушки. Гости не запускают вторую симуляцию врагов.
- Деньги подбираются один раз и начисляются всем. Общие задания, прогресс генератора/зоны и награды синхронизируются. Дроп виден всем; его награда достаётся открывшему.
- Покупки, патроны, состояние оружия и аптечки принадлежат конкретному игроку. Упавшего товарища можно поднять на E в пределах 2,5 м, восстановив 50 HP.
- Открытие магазина/меню останавливает только управление этим игроком: сетевой мир продолжает жить.
- При кратком обрыве WebSocket клиент автоматически возвращается в свой слот; сервер резервирует его на 120 секунд. Повторные снимки состояния не начисляют награды повторно. Это восстановление соединения в работающем приложении, а не загрузка матча после перезапуска игры.

Хост должен оставаться в игре; миграции хоста нет. При закрытии его лобби матч завершается у гостей. HTML и Godot могут использовать один адрес сервера, но **не могут войти в одну комнату**: физика и генерация версий различаются. Steam-интеграции пока нет.

## Проверка разработчиком

`python3 scripts/test-godot-coop.py all` — запускает два настоящих Godot-клиента сначала через LAN ENet, затем через локальный WebSocket-сервер. Проверяются seed, выстрел гостя, общие деньги, удержание E 15 секунд на генераторе, повторная доставка наград и оживление хоста. Нужны Godot в PATH, Python 3 и установленные npm-зависимости.

`npm test` дополнительно проверяет четыре места в серверной комнате, разграничение полномочий, код, возврат в слот и изоляцию HTML-комнат.
